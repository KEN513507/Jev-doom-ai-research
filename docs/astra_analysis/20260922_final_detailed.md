# Astra 詳細診断 (2026-09-22 夜) - 修正方針

## 中心方針
「命令の完了時キャンセル」+「USE後の反応確認」
TTL短縮だけでは不十分。

## 1. Stale order対策
- 旋回開始時の方位を保存し、目標角度到達で order_id を完了扱い→解除
- 敵出現・脱出成功・エピソード変更でも適用条件喪失の命令はキャンセル
- TTLは暴走防止の上限として残す。秒数だけで旋回完了を判断しない
- 非同期応答に episode・観測時刻を付与、古い返答による命令復活を防ぐ

## 2. DoorWaiter 誤発火防止
- 「USE実行→無条件30tic待機」を廃止
- USE後は短い観測期間で姿勢固定、前方深度・開口変化を確認
- 反応あれば待機継続、通行可能なら早期解除
- 無反応なら打ち切り、位置+向きごとに再試行抑制
- 鍵不足通知は別扱い
- 深度だけでドア断定不可 → 「開いた反応の確認」として実装

## 3. 集計分離
同一 episode_id・decision_id・tic で記録:
  Jev提案 → Reflex補正 → DoorWait抑制 → 実ボタン + 実行tics

Gemini も「新規発行」「再提示」「完了/キャンセル」を分離。
Reflex後の選択も DoorWaitで無操作なら実行回数に数えない。
